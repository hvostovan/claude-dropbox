# Architecture
> Общие инварианты воркшопа — не зависят от конкретной задачи примера (`sample-task.md`),
> одинаковы для всех трёх команд (Python/JS/Java).

## Инварианты
1. Данные хранятся только в памяти процесса — без БД. Сброс при перезапуске осознанно допустим
   для целей воркшопа.
2. Рендеринг — только на сервере (server-side), полными HTML-страницами. Без отдельного
   JS-фреймворка на фронте и без AJAX/fetch — формы отправляются обычным POST с перезагрузкой
   страницы.

## Обязательные / запрещённые паттерны
- Обязательно: server-side rendering (свой шаблонизатор под стек — см. `02-engineering-standards.md`).
- Запрещено: подключать React/Vue/аналоги или БД — усложняет сравнение SDD-процесса между
  командами и не нужно для целей воркшопа.

## Схема
Нет отдельной схемы — архитектура одна и та же во всех трёх командах (backend + server-side
шаблонизатор + in-memory хранилище), различается только языком/фреймворком. Модель данных
конкретной задачи сюда не входит — она формируется в спецификации на Этапе 2.

## Ключевые интеграции и зависимости
Нет — воркшоп замкнут внутри репозитория, без внешних систем. Если у конкретной задачи
появятся интеграции — фиксируются в спецификации (Этап 2), не здесь.
