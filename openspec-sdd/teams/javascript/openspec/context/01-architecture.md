# Architecture
> Общие инварианты для всех трёх команд (Python/JS/Java) — про домен, не про стек.

## Инварианты
1. Данные (эпики, задачи) хранятся только в памяти процесса — без БД. Сброс при перезапуске
   для MVP осознанно допустим.
2. Задача с несколькими исполнителями размножается: отдельная запись на каждого исполнителя,
   а не одна задача "на двоих".
3. Задача не обязана быть привязана к эпику — допустима задача без привязки ("общая").
4. Рендеринг — только на сервере (server-side), полными HTML-страницами. Без отдельного
   JS-фреймворка на фронте и без AJAX/fetch — формы отправляются обычным POST с перезагрузкой
   страницы.

## Обязательные / запрещённые паттерны
- Обязательно: server-side rendering (свой шаблонизатор под стек — см. 02-engineering-standards.md).
- Запрещено: подключать React/Vue/аналоги или БД — усложняет сравнение SDD-процесса между
  командами и не нужно для MVP.

## Схема
Нет отдельной схемы — архитектура одна и та же во всех трёх командах (backend + server-side
шаблонизатор + in-memory хранилище), различается только языком/фреймворком. Детали продукта и
модель данных — см. `task.md` в `claude-dropbox`.

## Ключевые интеграции и зависимости
Нет — MVP без внешних систем (ни БД, ни трекера). Интеграция с API корпоративного трекера для
автозаведения задач — следующий этап, вне рамок текущего MVP.
